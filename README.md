# 20·5·1·5 — 一分钟讲明白，再被外行追问

20 分钟研究，5 分钟准备，1 分钟讲明白，5 分钟被一个完全不懂的人追问。

灵感来自抖音上「20分钟研究 / 5分钟准备 / 1分钟呈现」的自我挑战：画面挂倒计时，
口播时实时记「卡壳 x1 / 口齿不清 x1」。这里把那套规则做成了网页，并加了第四段。

## 为什么加第四段

计数器只能告诉你「你卡了 3 次」。一个装作什么都不懂的听众能告诉你「你压根没讲明白」。
外行有个专业人士没有的武器：他能问「所以这个跟我有啥关系」——这个问题打死一半的技术分享。

## 设计取舍：这一页不跑 AI

审问由**你自己的 ChatGPT 客户端**完成（语音模式最好使），这一页只负责计时、给话术、收对话、算账。

这么分的三个理由：

- **零成本**。你订阅里已经含语音，边际成本是 0。走 OpenAI Realtime API 大约 $0.05/分钟，一场 5 分钟就是一块八。
- **零后端**。用 API 就必须有服务端铸临时 token（key 绝不能进浏览器），一下就从静态站变成要托管函数。现在仍是三个静态文件。
- **语音质量**。客户端的语音交互比自己搭一套顺。

代价是有一步手动：对话结束后你点复制、粘回来。换到的是没有 key、没有账单、不会哪天被 API 改版打断。

## 四段流程

| 段 | 默认 | 这一页做什么 |
|---|---|---|
| 研究 | 20 分钟 | 随便查，笔记记在页面上 |
| 准备 | 5 分钟 | 明确拦你：不许再查，只能把攒的料串成线 |
| 呈现 | 1 分钟 | 四个计数按钮：卡壳 / 口齿不清 / 跑题 / 嗯…那个（空格 = 卡壳）|
| 受审 | 5 分钟 | 给你人设话术，念给 ChatGPT；答完把对话粘回来 |

## 审问强度三档

人设不写「你什么都不懂」——那样模型会演成笨蛋，只会问「啥意思啊」，没杀伤力。
写的是**不懂术语但生活经验极其扎实**，你一含糊他就用日常场景怼你。

- **好奇宝宝** — 顺着你问，只求听懂，3~4 轮
- **正常外行** — 拿生活经验对照你的说法，必问一次「这跟我日常有啥关系」，4~6 轮
- **杠精** — 揪住一个词不放直到你承认边界，还会问「这个说法什么情况下不成立」，5~7 轮

## 记录能力

- **对话解析** — 粘贴的对话会自动挑出「它问了你什么」，生成勾选清单。勾掉答得上的，剩下的就是欠账，也是下一场的研究清单。
- **录音** — 可选，呈现+受审全程，结束后回放。第一次听自己的录音会不舒服，那正是有用的部分。
- **录屏** — 可选，`getDisplayMedia`，整场录下来，复盘页给下载链接。桌面浏览器才支持，iOS Safari 不支持。
- **日历提醒** — 生成 `.ics` 文件导进系统日历。网页版没法在关掉标签页后弹通知（那需要服务端推送），交给系统日历反而更可靠。
- **场次历史** — 存 localStorage，最多 30 场。

## 关于「读取 ChatGPT 客户端的对话」

没有自动通路。没有开放 API 能读客户端的本地会话，写浏览器插件去扒也随时会被改版打断。
所以这里选了手动粘贴 + 本地解析：多一步操作，换来零依赖、不会突然坏。

解析逻辑在 `parseQuestions()`，正反两面都测过：8 句真问句全收（包含句末是句号的
「"预示"是什么意思，能不能不用这个词再讲一遍。」），8 行陈述句零误收。识别不准也没关系，
清单可以手动改。

## 技术

三个静态文件，无构建步骤，无依赖，无后端，无账号，无埋点。

```
index.html          235 行
assets/style.css    236 行
assets/app.js       552 行
```

计时 `setInterval`，提示音 WebAudio 现场合成，录音/录屏 `MediaRecorder`，持久化 localStorage。

## 本地跑

```bash
python3 -m http.server 8899
# http://127.0.0.1:8899
```

录音和录屏需要 HTTPS 或 localhost 才能拿到权限。

## 部署

任何静态托管都行。当前跑在 GitHub Pages 上。Vercel 也可以：

```bash
vercel --prod
```

## 隐私

笔记、对话、场次记录只写这台设备的 localStorage。录音和录屏是内存里的 blob，
关掉页面就没了（要留就在复盘页下载）。没有任何请求发往任何服务器——因为没有服务器。
